## 证据与范围决定

- P2：原 net.py 在同步导入时创建连接池。用现有 aiohttp 3.9.5 复现：随后进入 asyncio.run，session 不属于当前循环，请求直接抛出 `Timeout context manager should be used inside a task`。
- P2：Live.deinit 只关会话，不关共享池。真实本机 HTTP 请求结束后，池仍开放并保留 1 条连接，Application 没有统一清理入口。
- 这些证据不表示普通 Docker 录制必然失败；Uvicorn 通常会在运行循环中加载模块。
- 结构决定：Local Fix；执行决定：Staged Refactor，仅处理网络资源边界，不重写应用。
- 范围：net、live、helpers、cover_downloader、application 及一个测试文件。预算 6 文件 / 250 行；实际 6 文件 / 217 行增删。单独附此维护说明。
- 用户授权：本地重构下一版本，不推断为云端发布许可。技能路由 code-quality-workflow；A0 已核对目标、红线和验收，参考快照 2026-08-18，无设计候选。

## 行为约定与实现

- 导入模块不创建连接池。get_connector 在当前运行循环首次需要时创建，同循环共享、跨循环隔离。
- close_connector 只移除并关闭当前循环的池；重复关闭安全，下次使用会创建新池。
- 应用全部任务成功停止和销毁后关闭池。若停止或销毁失败，保留池供仍在运行的任务和后续重试使用，不在 finally 中盲目断开连接。
- Live、房间/登录辅助请求、封面下载均改用同一入口。关闭单个会话不会误关其他会话使用的池。
- 保留每循环共享的 200 连接上限、10 秒超时、环境代理、会话 Cookie 隔离及原请求错误处理。
- 不改配置字段、HTTP 业务接口、录制格式、礼物/XML、依赖或 Docker 发布流程。
- 内部 API 的旧 `net.connector` 全局对象已移除；自行导入该内部对象的脚本需迁移到当前循环中的 get_connector。

## 单独调用内部功能的清理约定

正常网页运行由 Application 负责清理。独立脚本必须在所有会话和请求结束后、事件循环关闭前显式关闭池；Live 对象也必须在运行中的异步函数内创建，并先调用 deinit 关闭会话。

```python
import asyncio
from blrec.bili.helpers import room_init
from blrec.bili.net import close_connector

async def main():
    try:
        return await room_init(123)
    finally:
        await close_connector()

asyncio.run(main())
```

## 未解决边界与下一步

- 本轮不支持同一循环内多个 Application 实例的独立关闭；也不自动清理忘记调用 close_connector 的外部脚本。缓存依赖明确的生命周期，不假称弱引用能自动回收。
- 网页内重启时应避免并发验证 Cookie、添加任务等管理请求；共享池关闭可能中断这些请求，尚未实现管理操作的无损并发重启。
- 停止/销毁任务本身失败时，整个应用的最佳努力清理尚未重构。保留池不是证明残余任务已经停止。
- IPv4 参数解析、循环导入、组件内部部分初始化失败及长期运行资源占用仍为后续独立候选；本轮不混修。
- 本地阶段未执行 Docker 验收；本次云端结果见下文，不沿用 2.0.2 的结果。真实直播和长时断网重连仍未验收。
- 发布门槛：本次已获准推送发布，完成全新双架构和公开拉取启动检查后更新正式标签。
- 撤回边界：可单独撤回 73e947d；不重置工作目录，不触碰已有配置、Cookie、录像或旧版本镜像。
